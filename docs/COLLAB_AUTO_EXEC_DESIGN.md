## 一、背景与目标

- U3（TASKS.md）：协作条「自动执行 开/关」选项，2026-09-08 用户验收 D1-D4 时确认的增项。原始诉求：**对话内协作发送后四阶段（讨论→结论→执行→验收）无条件全链自动跑完，成本不可控**（执行阶段是 Agent+工具循环，费用大头）。
- 目标：协作条增加开关——**开** = 维持现状全链自动；**关** = 讨论与结论完成后暂停，由用户决定是否继续执行。

## 三、方案

### 3.1 开关语义（Q1）

- **开（自动）**：与现状完全一致——①讨论 → ②结论 → ③执行 → ④验收 一气呵成。
- **关（手动，默认）**：发送后自动跑 ①讨论 + ②结论（用户主动发送即是要讨论，不设闸）；② 上屏后**暂停**，追加一条「⏸ 协作已暂停」系统气泡 + 常显按钮行：
  - **「⚙ 执行并验收」**：继续 ③执行 → ④验收（一键续跑两段；验收是单次裁判调用，只在执行后有意义，不单独设闸）；
  - **「▣ 就此打住」**：仅收起按钮行；该 run 停在 concluded 状态，后续可从 🗂 档案手动执行/重试（CollabRunDialog 已有该能力）。

### 3.2 暂停点交互与状态（Q3/Q5）

- 暂停时 `setSending(false)`——发送钮恢复，用户可继续正常对话；点「执行并验收」后重新 `setSending(true)`，复用现有失败处理（异常 → 「协作失败（已中止）」）。
- ③④ 逻辑从 `startEnterpriseCollab` 抽出私有方法（如 `finishCollab(run, judgeAlias, firstAlias)`），自动/手动两路径共用，不复制代码。
- 按钮行为常显（非悬停）——它是待办动作，不是消息操作；样式沿用 `.bubble-copy` 类按钮 + 主题令牌，明暗随动。

### 3.3 会话守卫（Q4）

发起时捕获 `enterpriseSessionId`；点击「执行并验收」时若当前会话 ≠ 发起会话 → 不执行，提示「该协作属于会话「X」，请切回后继续，或在 🗂 档案中操作」。跨会话续跑会把 ③④ 消息写进错误会话的视图，误导阅读（服务端 run 归属不变）。

### 3.4 不做的事（边界）

- 不 gate 讨论/结论（Q1 语义内定）；不做暂停后的超时自动续跑/自动取消——挂起无成本，用户可随时点按钮或去档案处理。
- 不做运行中打断协作链（现状本就无 cancel，维持）；不动 CollabRunDialog（档案）与服务端。
- 重启/会话恢复后暂停按钮不复活（内存态）：该 run 在服务端停在 concluded，档案中可见可继续——已有能力覆盖。

## 四、决策点（编号回复，A/B/C）

- **Q1** 开关语义：**A** 关=讨论+结论自动、执行+验收需点击（推荐，闸在费用大头且交互最少）/ B 关=四阶段逐段确认（讨论后也停，3 次点击过碎）/ C 关=只讨论+结论且不可续跑（语义变截断，功能受损）
- **Q2** 默认值与持久化：**A** 默认关 + 内存态，重启回默认关（推荐，与模板/轮次/裁判等协作条控件一致）/ B 默认关 + ui.yml 持久化（多一处存储，意义有限）/ C 默认开（维持自动现状——与"烧钱"诉求相悖）
- **Q3** 暂停交互：**A** 「⏸ 已暂停」气泡 + 常显按钮「⚙ 执行并验收」+「▣ 就此打住」（推荐）/ B 两段分开点（执行、验收各一次，多一次点击）/ C 仅输入行上方出现临时横条按钮（离开消息流上下文，阅读断裂）
- **Q4** 会话切换守卫：**A** 点击时校验会话一致性，不匹配仅提示不执行（推荐）/ B 允许跨会话继续（③④ 写进错误会话视图）/ C 切换会话即作废按钮（误切后无法恢复，只能去档案）
- **Q5** 开关读取时机：**A** 发送时捕获（与模板/轮次/裁判一致，运行中切换不影响本轮，下一轮生效）（推荐）/ B ② 完成时实时读取（中途切换行为漂移，难以解释）
