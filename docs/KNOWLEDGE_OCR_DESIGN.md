# 知识库 OCR 设计（KNOWLEDGE_OCR，2026-09-06 待确认）

> 需求：图片/扫描件（jpg/png/pdf 无文本层等）入库，此前记为「OCR 规划中」。

## 1. 候选方案
| 方案 | 形态 | 优 | 劣 | 依赖 |
|---|---|---|---|---|
| A. 本地 PaddleOCR | ONNX 模型（Java 侧 ONNX Runtime 或调 python） | 离线、中文准、隐私好、一次投入 | 模型体积/首次下载、CPU 较慢、需网络首次 | onnxruntime + paddle 模型（约 4-15MB 起） |
| B. 云端 OCR | 阿里云 OCR / 腾讯 OCR HTTP | 接入快、准、维护零 | 需云账号/Key、按次计费、数据出境顾虑 | 云 API |

## 2. 决策点（请编号确认/修改）
| # | 决策 | 默认建议 |
|---|------|---------|
| 1 | **方案** | **A 本地（PaddleOCR ONNX）** 优先：个人/企业本地语义 & 离线可用；如追求零维护选 B（需 Key） |
| 2 | **范围** | 仅「图片 + 无文本层 PDF」走 OCR；有文本层文件仍走既有解析 |
| 3 | **接入形态** | 新增 `OcrEngine` SPI（本地实现 + 可选云实现），图片→文本后复用现有 PlainText 解析/分块/向量化链路 |
| 4 | **执行位置** | 服务端上传/桌面上传共用；首帧默认启用需配置开关 `omniforge.knowledge.ocr.enabled`（默认关，避免体积/耗时突增） |
| 5 | **护栏** | 单图 ≤10MB、分辨率降采样上限、超时（如 30s/图）、失败记日志不阻塞其它文档 |
| 6 | **模型分发** | PaddleOCR 模型首次按需下载（缓存目录），与 embedding 模型分发策略一致 |

## 3. 不做（v1）
- 表格结构还原/版面分析（仅整图→文本）；手写体优化；多语言（默认中英）。
